# Авторские тексты — фронтенд

Лабораторная работа №6 по теме «Расчёт лексического разнообразия авторских текстов».
Ветка — `lab6-author_texts-api`. ЛР-5 сохранена в `lab5-author_texts-react`.

Стек: React 19, TypeScript 5, Vite 7, React Router 7, React-Bootstrap 2,
Bootstrap 5, Redux Toolkit 2, React-Redux 9, Axios 1.

## Запуск

Требуется Node.js 22.12+ и npm. В репозитории backend запустить контейнеры:

```powershell
cd ../lexical-diversity-backend
docker compose --profile full up -d --build
```

Контейнер backend автоматически применяет миграции Alembic и seed.
Backend работает на порту 8000, PostgreSQL — 55432, Redis — 6379,
MinIO — 9000, консоль MinIO — 9001, Adminer — 8080.

Во фронтенде:

```powershell
cd ../author_texts-frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173/author_texts`. Пример существующей демонстрационной
учётной записи: `researcher_1` / `author_texts_demo`. Если её пароль был изменён,
использовать свой пароль или зарегистрировать новый аккаунт на странице входа.

Параметры proxy описаны в `.env.example`; при необходимости скопировать его
в `.env.local` и перезапустить Vite. Адрес API задаётся через
`VITE_AUTHOR_TEXTS_API_TARGET`, MinIO — через `VITE_AUTHOR_TEXTS_MEDIA_TARGET`.

## Страницы и действия

В нижнем меню четыре пункта: «Лента», «Добавление», «Корпус», «Вход»/«Выход».
Круглая кнопка «!» в углу карточки корпуса открывает дополнительный экран
«Подробнее». Отдельного пункта меню для него нет.

| Страница | Содержимое | Действия |
|---|---|---|
| Корпус `/author_texts` | Фильтр минимальной длины; обложки, названия, количества токенов и лайков | «Применить», «Сбросить»; карточка открывает ленту; «!» открывает подробности; вошедший пользователь может удалить свои тексты |
| Лента `/author_texts/feed` и `/author_texts/feed/:author_text_id` | Видео, название, краткое описание, количества токенов и лайков | «Следующий», «Больше/Меньше» для длинного описания; после входа — поставить или снять лайк. Атрибутов и верхней кнопки «Корпус» в ленте нет |
| Подробнее `/author_texts/:author_text_id` | Обложка, описание, количества токенов, TTR, таблица названий и значений атрибутов | Возврат к корпусу; изображение на всю ширину без белых полей |
| Добавление `/author_texts/add` | Первый шаг: название, изображение и видео. Второй: описание, общее и уникальное количества токенов, дополнительные характеристики | До отправки видны выбранные фото и видео; кнопки «Выбрать видео» и «Выбрать изображение» меняют предпросмотр. «Далее» создаёт черновик и загружает файлы в MinIO. «Опубликовать» публикует карточку. Существующий черновик восстанавливается при открытии страницы |
| Вход `/author_texts/login` | Имя пользователя и пароль; переключение на регистрацию | Войти, зарегистрироваться. После входа меню показывает «Выход», добавление становится доступным |

Гость может читать корпус, подробности и ленту. Изменения требуют входа.
Кнопка удаления показывается только для карточек с `is_owner=1` и вошедшего
пользователя; права дополнительно проверяет backend. Удаление логическое.
Лайк передаёт `value=1`, снятие — `value=0`; состояние берётся из `is_liked`. Вкладка «Лента» открывает `/author_texts/feed` без ID; карточка корпуса передаёт ID выбранного текста.

## Redux и авторизация

`src/store/author_texts_store.ts` создаёт store через `configureStore`:

- `author_texts_auth` — текущий пользователь и ожидание входа/выхода;
- `author_texts_filter` — выбранная и применённая минимальная длина;
- `author_texts_operations` — черновик, число выполняемых запросов, ошибки и обновление списка.

Фильтр сохраняется при переходах между страницами. При выходе пользователь,
черновик и фильтр очищаются. Состояние Redux хранится в памяти: после F5 интерфейс
снова гостевой, а HttpOnly cookie может оставаться в браузере до выхода или
истечения сессии Redis. Для действий пользователя нужно снова выполнить вход. Это соответствует пункту 9 порядка показа [ЛР-6](https://github.com/iu5git/Web#лабораторная-6): интерфейс Redux после F5 гостевой, сессия в cookie остаётся.
Пароль и значение cookie в Redux и localStorage не сохраняются.

Вход, регистрация и выход написаны вручную через Axios. Кнопка «Создать аккаунт и войти» выполняет регистрацию, затем вход. Если имя уже занято (409), выполняется вход с введённым паролем; при неверном пароле показывается ошибка существующего аккаунта. После успешного входа
ответ пользователя передаётся в Redux обычным action. Браузер сам сохраняет
и отправляет `author_texts_session` с флагом HttpOnly и путём `/api`.

Запросы домена авторских текстов выполняются через сгенерированный Axios-клиент
в `createAsyncThunk`; стандартный thunk middleware подключён Redux Toolkit.
При выполнении запросов показывается блокирующая анимация, кнопки форм отключаются.
Собственный Context не используется; Provider относится к React-Redux.

## API, кодогенерация и proxy

`src/api/author_texts_api.generated.ts` сгенерирован из OpenAPI backend.
Для повторной генерации при запущенном backend:

```powershell
npm run author_texts:generate-api
```

Файл генерации вручную не редактируется. `src/api/author_texts_client.ts`
настраивает общий Axios instance: `baseURL=/api`, `withCredentials=true`,
тайм-аут 8 секунд. Загрузка файлов имеет увеличенный тайм-аут.

| Действие | Метод API |
|---|---|
| Корпус и фильтр | `GET /api/author_texts?min_text_length=100000` |
| Первая, выбранная и следующая карточка | `GET /api/author_texts/feed`, query `author_text_id`, `next=true` |
| Черновик пользователя | `GET /api/author_texts/draft` |
| Создание с файлами | `POST /api/author_texts`, multipart: название, изображение, видео |
| Публикация | `PUT /api/author_texts/{id}/publish` |
| Удаление своей карточки | `DELETE /api/author_texts/{id}` |
| Лайк и снятие лайка | `POST /api/author_texts/{id}/like` |
| Регистрация, вход, выход | `POST /api/author_texts_users/register`, `/login`, `/logout` |

Vite пересылает `/api` на backend и сохраняет браузерный Host для проверки Origin.
Второй маршрут `/author_texts_media` пересылается в бакет `author-texts-media`
MinIO. Компоненты медиа заменяют абсолютный MinIO URL на этот относительный путь.
Оба proxy действуют и при `npm run preview`. При другом размещении нужны
аналогичные reverse proxy и SPA fallback на `index.html`.

## Mock и дополнительные атрибуты

При недоступном backend, тайм-ауте, ошибке сервера 5xx или некорректном ответе
гостю показываются mock-данные. Для принудительного гостевого режима mock указать
`VITE_AUTHOR_TEXTS_DATA_MODE=mock` в `.env.local` и перезапустить Vite.
Авторизованные запросы и изменения никогда не подменяются mock. Пустой успешный
список остаётся пустым; 404 карточки показывает «Текст не найден».

Атрибуты приходят в массиве `attributes`: ID, название, значение.
Экран «Подробнее» показывает их в нижней части таблицей из двух колонок.
В форме публикации доступны характеристики, встречающиеся у загруженных карточек,
и характеристики текущего черновика. Пустые значения не отправляются.
Названия хранятся в `author_texts_attributes`, значения — в
`author_texts_attribute_values` backend. Новые столбцы таблицы текстов не нужны.

Фото и видео для mock находятся в `src/assets/media/`, резервные — в `public/media/`.
При пустом или недоступном источнике подставляется резервный файл. В пустой форме добавления до выбора файлов фото и видео не показываются. Предпросмотр выбранных файлов использует временные object URL; они освобождаются при замене файла и уходе со страницы. Стили —
`src/author_texts_styles.css`: розовый фон `#FCE7F3`, белые карточки, кнопки `#3F3F46`.
